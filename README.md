# natasha-server

HTTP-сервис, который достаёт из русского текста ФИО, адреса, даты и суммы. Отдаёт JSON.

ФИО, даты и суммы разбирает [natasha](https://github.com/natasha/natasha). Адреса разбирает [Pullenti](http://pullenti.ru/), потому что у natasha они получаются слабо. Всё работает локально на CPU. Внешних API и ключей нет.

Это форк [wild5r/natasha-server](https://github.com/wild5r/natasha-server). Оригинал написан под natasha 0.x и Python 3.5 и больше не собирается.

## Запуск

```
docker build -t natasha-server .
docker run -d -p 127.0.0.1:8080:8080 -m 1g --restart unless-stopped natasha-server
```

Сервис стартует 10-15 секунд, пока грузятся модели. Готовность можно проверить так:

```
curl localhost:8080/health
```

Сервису нужно около 450 МБ памяти. Лимит `-m 1g` лучше не убирать. Если что-то пойдёт не так, Docker перезапустит контейнер, а сервер не ляжет целиком.

Swagger с описанием API открывается на http://localhost:8080/docs

## Запрос

```
curl localhost:8080/natasha \
  -H 'Content-Type: application/json' \
  -d '{"data": "Иванову Петру Сергеевичу 5 марта 2024 года выделили 300 тысяч рублей на ремонт по адресу г. Москва, ул. Тверская, д. 13, кв. 5."}'
```

В `data` передаётся текст. Максимум 20 000 символов, на текст длиннее сервис ответит 422. Лимит меняется переменной окружения `MAX_TEXT_LENGTH`.

Если добавить `"tokens": true`, в ответ придёт ещё разбор каждого слова. Это медленнее, поэтому по умолчанию выключено.

## Ответ

Это настоящий ответ на запрос выше:

```json
{
  "original_data": {
    "data": "Иванову Петру Сергеевичу 5 марта 2024 года выделили ...",
    "tokens": false
  },
  "names": [
    {"first": "Петр", "last": "Иванов", "middle": "Сергеевич"}
  ],
  "spans": [
    {
      "type": "PER", "start": 0, "stop": 24,
      "text": "Иванову Петру Сергеевичу",
      "normal": "Иванов Петр Сергеевич",
      "fact": {"first": "Петр", "last": "Иванов", "middle": "Сергеевич"}
    },
    {
      "type": "LOC", "start": 92, "stop": 98,
      "text": "Москва", "normal": "Москва", "fact": null
    }
  ],
  "addresses": [
    {
      "start": 82, "stop": 126,
      "text": "адресу г. Москва, ул. Тверская, д. 13, кв. 5",
      "normal": "улица Тверская д.13 кв.5; Москва",
      "geo": [{"type": "город", "name": "Москва"}],
      "streets": [{"type": "улица", "name": "Тверская"}],
      "house": "13",
      "flat": "5"
    }
  ],
  "dates": [
    {"start": 25, "stop": 42, "text": "5 марта 2024 года", "fact": {"year": 2024, "month": 3, "day": 5}}
  ],
  "money": [
    {"start": 52, "stop": 68, "text": "300 тысяч рублей", "fact": {"amount": 300000, "currency": "RUB"}}
  ]
}
```

`start` и `stop` везде означают позицию в исходном тексте. `text[start:stop]` вернёт найденный кусок.

### names

Список найденных людей. У каждого всегда три поля `first`, `last` и `middle`. ФИО приводится к именительному падежу. Если какой-то части в тексте нет, там будет `null`. Например, из "Путин заявил" получится только `last`.

### spans

Все сущности, которые нашла natasha. Типов три: `PER` для людей, `LOC` для мест и `ORG` для организаций. В `normal` лежит нормальная форма, в `fact` разбор на части. `fact` заполняется только для людей.

### addresses

Один объект на каждое упоминание адреса. Если адрес встречается в тексте дважды, придёт два объекта.

В `normal` адрес целиком в нормальном виде. В `geo` цепочка от крупного к мелкому, например область, район, деревня. В `streets` улица. Улиц бывает несколько, если адрес на перекрёстке.

Остальные поля приходят, только если они есть в тексте:

| Поле | Что это |
|---|---|
| `zip` | индекс |
| `house` | дом |
| `corpus` | корпус |
| `building` | строение |
| `flat` | квартира |
| `office` | офис |
| `plot` | участок |
| `block` | блок |
| `box` | гараж или бокс |
| `porch` | подъезд |
| `floor` | этаж |
| `kilometer` | километр трассы |

### dates и money

Даты приходят как `year`, `month` и `day`. Суммы приходят как `amount` и `currency`. Если часть даты не указана, её в ответе не будет.

### tokens

Есть только при `"tokens": true`. Для каждого слова отдаются лемма, часть речи, морфология и связь в синтаксическом дереве:

```json
{"text": "Иван", "start": 0, "stop": 4, "lemma": "иван", "pos": "PROPN",
 "feats": {"Animacy": "Anim", "Case": "Nom", "Gender": "Masc", "Number": "Sing"},
 "head_id": "1_0", "rel": "root"}
```

## Что работает плохо

- Адрес в нижнем регистре без города не находится. "ленинский проспект 32" не найдётся, а "Ленинский проспект 32" найдётся. Для текстов из чатов это стоит учитывать.
- Адреса не сверяются с ФИАС. Сервис только раскладывает адрес на части. Опечатки он не исправит.
- Буква ё заменяется на е. "Ёлкин" станет "Елкин", "Орёл" станет "Орел".
- В `text` адреса иногда попадает лишнее слово перед ним, как "адресу" в примере выше. На разбор это не влияет.
- Некоторые названия улиц Pullenti сокращает. Например, "50-летия Октября" превращается в "50 Октября".

## Разработка

Чтобы не пересобирать образ после каждой правки, можно подключить код папкой:

```
docker run --rm -it -p 8080:8080 -v $(pwd)/src:/app natasha-server
```

После правки контейнер нужно перезапустить.

Код лежит в двух файлах. В `src/natasha_json_server.py` сервер и всё, что делает natasha. В `src/addresses.py` разбор адресов через Pullenti.

`setuptools<80` в `requirements.txt` закреплён специально. pymorphy2 и Pullenti импортируют `pkg_resources`, а в новых версиях setuptools его нет.

## Лицензия Pullenti

Pullenti бесплатен только для некоммерческого использования. Для коммерческого проекта нужно купить лицензию на [pullenti.ru](http://pullenti.ru/). Без лицензии разбор адресов придётся отключить. Для этого надо убрать `addresses.py`, его импорт и поле `addresses` в `natasha_json_server.py`.
